1. **Accepts non-HTTP dates as valid (missing required GMT in IMF-fixdate).**  
   - **Input:**  
     `value = "Wed, 21 Oct 2015 07:28:00"`  
     `now = datetime.datetime(2015, 10, 21, 7, 27, 0, tzinfo=datetime.timezone.utc)`  
   - **What happens:** returns `60.0`.  
   - **Why this is a defect:** This string is not a valid HTTP-date format (IMF-fixdate requires `GMT`), so per task it should be treated as unparseable and return `0.0`.

2. **Accepts timezone-offset dates that are not valid HTTP-date syntax.**  
   - **Input:**  
     `value = "Wed, 21 Oct 2015 07:28:00 -0500"`  
     `now = datetime.datetime(2015, 10, 21, 7, 27, 0, tzinfo=datetime.timezone.utc)`  
   - **What happens:** returns `18060.0`.  
   - **Why this is a defect:** HTTP Retry-After uses HTTP-date, which is GMT-based; accepting arbitrary RFC 2822 timezone offsets is overly permissive and should be unparseable (`0.0`).

3. **Very large valid delta-seconds can incorrectly return 0.0 due to float overflow.**  
   - **Input:**  
     `value = "1" + "0" * 400`  (a valid non-negative integer token)  
     `now = any valid UTC datetime`  
   - **What happens:** `float(int(value))` overflows, exception is caught, function returns `0.0`.  
   - **Why this is a defect:** Input is parseable as delta-seconds, but function reports it as unparseable (`0.0`), violating the stated behavior for delta-seconds.
