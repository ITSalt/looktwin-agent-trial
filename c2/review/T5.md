1. **Incorrect handling of bases with exactly two leading slashes (`//...`)**  
   The function deliberately rewrites `base_norm` from `//...` to `/...`, which changes the base path instead of just normalizing it.

   - **Breaking input:**  
     `base="//tenant"`  
     `user_path="docs/file.txt"`
   - **Current output:** `"/tenant/docs/file.txt"`
   - **Why this is a defect:** Under POSIX path rules, exactly two leading slashes are special/implementation-defined and are preserved by `posixpath.normpath`. Rewriting `//tenant` to `/tenant` means the returned path is no longer inside the original `base` path string provided by the caller, violating the function contract.
