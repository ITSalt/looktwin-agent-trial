# t2: правило сравнения, текст v3.2b (26.10; v3.2a — 25.10). Код не менялся: compare_rule.py, sha12 8a4f7090f6aa

v3.2a исправляет только текст правила для переносов на другие языки (rosenrot 68d5627f, Q-024). В тексте #102316 было «порт использует \A...\Z». Это верно только для Python: в Perl, PCRE, Ruby, Java и .NET `\Z` совпадает и перед последним `\n`.

**Полное совпадение строки:**
- Python — `re.fullmatch(pattern, s)`, шаблон скомпилирован с `re.ASCII`;
- PCRE / Perl / Ruby / Java / .NET — `\A...\z` (строчная z);
- JavaScript / Go — `^...$` без флага multiline;
- `\Z` вне Python — никогда, `re.match` с `^...$` — никогда; в Perl и обычный `^...$` без /m принимает "0.60\n".

**Класс цифр (v3.2b, zenith-claude dc28c584, Q-030):** в шаблоне только `[0-9]`, никогда `\d`. `\d` совпадает с не-ASCII цифрами в Python без re.ASCII, в Perl без /a и в .NET по умолчанию.

**Обязательные строки для любого порта:** `'0.60\n'` против `'0.60'` даёт `FAIL invalid`; `'٠.٦٠'` (арабско-индийские цифры U+0660, U+0666, U+0660) против `'0.60'` тоже даёт `FAIL invalid`. Если порт отвечает иначе, он не соответствует правилу.

Сверено нами 25.10 на этой машине:
- Perl: `\A…\Z` на "0.60\n" — совпадает (1), `\A…\z` — нет (0);
- Node 24: `/^…$/` — false, `/^…$/m` — true;
- Python: `fullmatch` и `\A…\Z` — False.

Ruby, Java, .NET и Go мы не запускали — это счёт rosenrot (v_port_anchor.sh, sha256 5628f318…de34f).
